# 02. Написание DDL-скрипта (База данных в коде)

## Задание

Напишите SQL-скрипт (`schema.sql`) для развертывания спроектированной структуры.

Инструкция к заданию:

Скрипт должен содержать:
1. Команды удаления таблиц, если они существуют (`DROP TABLE IF EXISTS...`), с учетом порядка зависимостей.
2. Команды создания таблиц (`CREATE TABLE`) с правильными типами данных (`VARCHAR`, `INT`, `DATE/TIMESTAMP`, `DECIMAL` для цен).
3. Явное описание ограничений (`PRIMARY KEY`, `FOREIGN KEY` `ON DELETE RESTRICT/CASCADE`).

## Реализация

### Порядок удаления таблиц

`DROP TABLE IF EXISTS` выполняется в порядке, обратном созданию — сначала зависимые, затем родительские:

1. `delivery_items`
2. `deliveries`
3. `products`
4. `partners`

### Порядок создания таблиц

`CREATE TABLE` выполняется в порядке зависимостей — сначала родительские, затем зависимые:

1. `partners`
2. `products`
3. `deliveries`
4. `delivery_items`

### Ключевые решения

- **PK** — `<сущность>_id`, тип `INT GENERATED BY DEFAULT AS IDENTITY` (позволяет вставлять ID из файлов при импорте).
- **Типы данных** — `VARCHAR` для строк, `INT` для целых, `DATE` для даты отгрузки, `NUMERIC(12,2)` для денежных сумм, `NUMERIC(2,1)` для рейтинга.
- **`partners.inn`** — `VARCHAR(12)` (10 цифр у юрлиц, 12 у ИП), `UNIQUE`, nullable.
- **`deliveries.partner_id`** — `ON DELETE RESTRICT` (нельзя удалить партнёра с отгрузками).
- **`delivery_items.delivery_id`** — `ON DELETE CASCADE` (при удалении накладной позиции удаляются).
- **`delivery_items.product_id`** — `ON DELETE RESTRICT` (нельзя удалить товар, используемый в отгрузках).
- **`delivery_items`** — `UNIQUE (delivery_id, product_id)` (один товар не может дважды встречаться в одной накладной).
- **CHECK-ограничения** — `quantity > 0`, `total_amount >= 0`.

# Обработка исключений и интерактивные уведомления (UX/UI)

## Постановка задачи

Система не должна падать при ошибках ввода. Пользователь должен получать
понятные инструкции по исправлению своих действий через системные диалоговые
окна.

Задача:

1. Реализуйте валидацию данных перед отправкой в БД (через конструкции
   `try...except`):
   - Проверка рейтинга: если введено не целое или отрицательное число,
     операция прерывается.
   - Проверка обязательных полей: наименование и email не должны быть пустыми.
2. Настройте вывод диалоговых окон (MessageBox) трех типов в зависимости от
   ситуации:
   - **Ошибка (Error):** Если данные не прошли валидацию или СУБД недоступна.
     Окно должно содержать понятный текст ошибки и порядок действий для её
     исправления (например: "Рейтинг должен быть целым числом от 0. Пожалуйста,
     удалите знаки препинания и повторите попытку").
   - **Предупреждение (Warning):** При нажатии кнопки «Назад» или «Отмена»,
     если пользователь уже успел изменить поля. Предупредите его о
     необратимости операции потери несохраненных данных.
   - **Информация (Information):** Уведомление об успешном сохранении или
     добавлении партнера в базу.
3. Проверьте, чтобы каждое диалоговое окно имело соответствующий заголовок и
   пиктограмму (иконку крестика, восклицательного знака или инфо-значка).

## Реализация

### Валидация

Функции валидации — в `app/core/validators.py`. Проверяются:

| Поле | Условие |
|------|---------|
| Наименование | не пустое |
| Email | не пустой, формат `name@domain.ru` |
| Рейтинг | целое неотрицательное число |
| Телефон | если заполнен — 11 цифр |

Валидация выполняется перед сохранением. При наличии ошибок форма не
закрывается, показывается диалог с полным списком ошибок.

### Диалоговые окна

| Тип | `QMessageBox` | Когда |
|-----|---------------|-------|
| Ошибка | `Critical` | Данные не прошли валидацию; СУБД отклонила запрос. |
| Предупреждение | `Warning` | Нажатие «Отмена» при наличии несохранённых изменений. |
| Информация | `Information` | Успешное добавление или сохранение партнёра. |

Каждое окно имеет заголовок и пиктограмму, соответствующие типу.

### Несохранённые изменения

Состояние формы на момент открытия сохраняется. При нажатии «Отмена»
текущее состояние сравнивается с исходным. Если различий нет — форма
закрывается без предупреждения. Если различия есть — выводится диалог
`QMessageBox.Warning` с вопросом о продолжении.

### Обработка ошибок СУБД

При сохранении перехватываются исключения `psycopg2.IntegrityError`
(нарушение ограничений) и `psycopg2.Error` (прочие ошибки СУБД). Текст
исключения выводится пользователю в `QMessageBox.Critical`.

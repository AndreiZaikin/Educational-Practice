# Разработка формы добавления/редактирования партнёра

## Постановка задачи

Интерфейс карточки партнёра должен строго соответствовать бизнес-требованиям и
поддерживать ввод разнородных типов данных.

Требования к полям формы из ТЗ:

- **Наименование** (текстовое поле).
- **Тип партнёра** (строго выпадающий список / ComboBox: ЗАО, ООО, ИП и т.д.).
- **Рейтинг** (целое неотрицательное число).
- **Адрес** (текстовое поле).
- **ФИО директора** (текстовое поле).
- **Телефон** и **Email компании** (текстовые поля с масками/подсказками).

Задача:

1. Сверстайте форму `PartnerEditWindow` согласно списку полей.
2. Реализуйте визуальные подсказки (плейсхолдеры или ToolTips) для полей ввода
   телефона и email, чтобы пользователь понимал ожидаемый формат ввода.
3. Добавьте код для комментирования: снабдите краткими и емкими комментариями
   только те участки кода, где логика неочевидна (например, инициализация
   выпадающего списка или передача ID партнера между окнами). Не комментируйте
   очевидные строки.

## Реализация

Форма `PartnerEditWindow` (`app/ui/partner_edit_window.py`) содержит поля:

| Поле | Виджет | Примечание |
|------|--------|------------|
| Наименование | `QLineEdit` | обязательное |
| Тип партнёра | `QComboBox` | заполняется из `partner_types`; первым пунктом — `<не выбран>` |
| Рейтинг | `QLineEdit` | плейсхолдер `Целое число от 0` |
| Адрес | `QLineEdit` | |
| ФИО директора | `QLineEdit` | |
| Телефон | `QLineEdit` | плейсхолдер `+7XXXXXXXXXX` |
| Email | `QLineEdit` | обязательное; плейсхолдер `name@domain.ru` |

Обязательные поля помечены `*` в подписях, под формой — примечание
«* — обязательные поля».

### Миграция рейтинга

Поле `partners.rating` приведено к целому неотрицательному числу скриптом
`alter_rating_to_int.sql`. Скрипт одноразовый, применяется к БД
однократно. Значения `NUMERIC(2,1)` округляются до ближайшего целого,
добавляется ограничение `CHECK (rating IS NULL OR rating >= 0)`.

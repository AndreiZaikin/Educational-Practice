# Наполнение интерфейса, отладка и стресс-тестирование

## Постановка задачи

Финальный этап сборки. Окно приложения должно ожить, наполниться реальными
данными из БД и пройти проверку на отказоустойчивость.

Задача:

1. Свяжите UI-компонент таблицы/списка с кодом из Подзадания 2. При запуске
   приложения на экране должен отображаться актуальный список партнеров, их
   контактные данные и автоматически рассчитанный процент скидки.
2. Проведите отладку: приложение должно корректно обрабатывать ситуации,
   когда у партнера вообще нет истории продаж (`SUM(quantity)` IS NULL или равен 0).
   Скидка в таком случае должна отображаться как 0%, а приложение не должно
   падать в ошибку (`NullPointerException` / `TypeError`).
3. Подготовьте проект к сдаче: соберите все файлы, проверьте код на отсутствие
   лишних закомментированных кусков и запустите финальный демонстрационный
   тест.

## Выполненные проверки

**Связь UI с БД.** `MainWindow._build_cards_area` вызывает
`repository.get_partners_with_discount()`. Карточки строятся из актуальных
данных БД. Отсутствие истории продаж обрабатывается в SQL-запросе через
`COALESCE(SUM(delivery_items.quantity), 0)`.

**Партнёр без продаж.** В `partners` добавлена запись без отгрузок.
Отображается со скидкой 0%; аварийного завершения нет.

**Ненулевая скидка.** Для партнёра создана отгрузка с объёмом в одном из
диапазонов скидки. Значение в карточке совпадает с результатом
`calculate_partner_discount`.

**Чистота кода.** Проход по `.py`-файлам на закомментированный код,
отладочные `print`, `TODO`/`FIXME`/`XXX`, временные файлы. Замечаний нет.
